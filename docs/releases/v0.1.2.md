# glibc-abilists v0.1.2

glibc-abilists 0.1.2 delivers corrected Signature::Exception documentation and the revised README. It changes the explanation of existing provenance limits, not the ABI data or collector behavior.

Original crates.io publication: **2026-11-01 (UTC)**, `2026-11-01T04:32:05.239152Z`.
Source: `v0.1.2` at `d0cf8ee40529880373286c500dd22b9c21d79e2c`. Package `glibc-abilists`
is available on crates.io and was non-yanked when checked on 2026-11-02.
These user-facing notes were backfilled on 2026-11-02; GitHub Release
publication timestamps are separate from the original package date.

## Changes

- Replace wording that treated every exception as a signed tag with an
  unavailable key. An explicit exception does not establish signature presence
  or a match to the configured exception key; its reported key can be empty.
  A configured reason is not proof that fallback checks ran.
- Ship revised dependency/API links, guide navigation, notice/credit wording and
  a package description bounded to recorded evidence.
- Maintain repository usage, collection, provenance, requirements and release
  guides with explicit online/offline limits. Those guides are not embedded in
  the crate; the packaged README links to GitHub.

## Upgrade

No downstream minimum requirement, lock update, rebuild or provider regeneration
is needed solely for this docs-only patch. Rust 1.90, public API/runtime behavior,
ABI data, generated source, keys, collector policy and upstream selection are
unchanged from 0.1.1. Consumers can deliberately select the patch in their locks
when they want its package documentation.

The previous collector code never enforced the guarantees that the old wording
suggested. This is not a newly introduced policy relaxation or a claim of data
compromise. Immutable 0.1.1 docs remain historical; 0.1.2 delivers the correction.

## Validation and limits

The retained release-tag CI run passed docs, Linux/Windows Rust checks, MSRV,
package verification and online collector comparison. The detailed
[0.1.2 qualification record](https://github.com/rustcommons/glibc-abilists/blob/main/docs/RELEASE-0.1.2.md)

The later collection-flow diagram and this history backfill are repository-only
follow-ups, not files shipped in 0.1.2. No new Rust suite is claimed for the
2026-11-02 documentation reconstruction. Missing adversarial exception tests and
offline trust/policy follow-up remain gaps, not enforced guarantees.
