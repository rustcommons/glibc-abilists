# glibc-abilists v0.1.0

The first published glibc-abilists library embeds glibc's own x86_64 Linux ABI lists, so consumers can look up raw ABI text and its recorded provenance without fetching glibc at runtime.

Original crates.io publication: **2026-10-11 (UTC)**, `2026-10-11T01:05:27.072634Z`.
Source: `v0.1.0` at `4ffb9f698264d7d8bd834f6f2b5e03926bdc02fb`. Package `glibc-abilists`
is available on crates.io and was non-yanked when checked on 2026-11-02.
These user-facing notes were backfilled on 2026-11-02; GitHub Release
publication timestamps are separate from the original package date.

## Changes

- Embed unmodified glibc 2.17–2.44 ABI lists for the x86_64 64-bit Linux ABI.
- Provide `release`, `releases`, `abilist` and `abilists`, release/file records,
  and `AbiList::verify()` to compare embedded text with its recorded SHA-256.
- Expose `LICENSE_TEXT` for redistribution. The crate/data are LGPL-2.1-or-later;
  the MIT collector remains unpublished. The library has no crate dependencies
  or build script.

## Upgrade

This is the initial published version, requiring Rust 1.90 or later. It is a
library dependency, not a `cargo install` command. Consumers supply parsing or
stub generation themselves. Preserve the LGPL text and notices when
redistributing ABI lists; the collector's license does not replace them.

## Validation and limits

The retained release-tag CI run passed Linux/Windows Rust checks, MSRV, package
verification and online collector comparison. The original workflow had no
separate rustdoc job. These checks concern the selected dataset and commands,
not arbitrary applications or distribution-patched glibc.

Signature exceptions and offline-write trust limits already exist in this
version. Hash comparison does not authenticate an exception tag or establish
runtime compatibility. Historical wording must not be read as enforcing
signature presence or a configured exception key. Use the current provenance
explanation; 0.1.2 later corrects the API wording.

The original date is the registry's UTC date. The annotated tag's local date
was 2026-10-10 (-05:00), also 2026-10-11 in UTC. No original GitHub Release
body was found during the 2026-11-02 inventory; these are reconstructed notes.
